# 01. Честно о выполнимости: можно ли тут сделать UEFI

## Короткий вывод

| Вопрос | Ответ |
|---|---|
| Есть готовый UEFI для MSM8937/8940? | **Нет.** Ни Renegade, ни форки edk2-msm не поддерживают этот SoC. |
| Технически возможно? | Да, но это порт с нуля, включая драйверы, которых нет в открытом виде. |
| Сроки (опытный разработчик, живое устройство, UART) | 2–4 месяца part-time |
| Без UART, «на глазок», через скриншоты | реалистично 30–50 % шанса дойти до загрузки ОС |
| Windows on ARM? | **Нет.** Нет ACPI-таблиц и драйверов; никто их не писал под 89xx. |
| Linux-дистрибутивы? | Да — это и есть достижимая цель. |

## Почему апстрим не помогает

`edk2-msm` (Renegade Project) устроен так:

* **SoC-независимое** — ядро EDK2, `QcomPkg/PrePi`, DXE-ядро, UEFI Shell, SimpleInit,
  `LinuxLoader`, общие библиотеки. Это всё есть в исходниках.
* **SoC-зависимое** — `Platform/EFI_Binaries/Drivers/<soc>/{SdccDxe,UFSDxe,ClockDxe,
  DALTLMM,I2C,SPMI,UsbInitDxe,UsbConfigDxe,UsbDeviceDxe,UsbMsdDxe,...}` — это
  **готовые .efi-бинарники из закрытых вендорских EDK-сборок**, поставляемые сабмодулем
  `edk2-msm-binary` отдельно для каждого поддерживаемого SoC.

Самое старое поддерживаемое семейство — `sdm660` (Snapdragon 660). Для msm8937
бинарей нет и взять их неоткуда: вендорские EDK-пакеты для 89xx в открытый доступ
не выкладывались.

## Что придётся написать (и сколько это стоит)

| Компонент | Что нужно | Оценка | Риск |
|---|---|---|---|
| Memory map + PEI/PrePi | уже набросано (`fw/.../PlatformMemoryMapLib.c`) | 1–2 дня | низкий |
| Framebuffer-консоль | `SimpleFbDxe` поверх сплэша LK по `0x90000000` | 1 день | средний: не будут работать смена режима/яркость |
| UART-консоль | `MsmUartSerialPortLib` (набросан) + разведённый UART на плате | 1–3 дня | **высокий**: на retail-платах debug-UART обычно отключён |
| GICv2 + arch timer | PCD + проверка нумерации PPI | 1–2 дня | низкий |
| **eMMC (SDCC/SDHCI)** | драйвер host-controller + power/clock через RPM/PMIC | **2–4 недели** | **очень высокий** |
| Кнопки (Vol±, Power) | TLMM GPIO + PMIC pwrkey по SPMI | ~1 неделя | средний |
| USB host (dwc3 + PHY) | инициализация PHY, роль, xHCI | 1–2 недели | высокий |
| Регуляторы/клоки (минимум для SDCC) | RPM-сообщения или прямое программирование | 1–2 недели | высокий |
| LinuxLoader / GRUB / загрузка дистрибутива | есть в апстриме, нужна адаптация | 3–5 дней | низкий |

Без eMMC-драйвера UEFI не увидит **ни одного раздела** — ни `boot`, ни microSD,
ни USB-флешку (для USB нужен ещё и dwc3). То есть «загружать любые системы»
упирается именно в этот драйвер.

## Четыре неизвестных, которые решают судьбу порта

1. **Умеет ли LK в AArch64?** Проверяется `tools/probe.ps1` за 2 минуты.
   Если нет — нужен EDK2-порт на AArch32 (ветка ARM), а это другой, более редкий
   и менее отлаженный путь (и 32-битные EFI-приложения).
2. **Есть ли доступ к UART?** Без логов отладка слепая: любая ошибка = чёрный экран.
   Варианты: тестовые площадки на плате под экраном, USB-UART на 1.8 В, либо
   «диагностика через framebuffer» (медленно).
3. **Хватает ли места и полномочий?** Размер `boot` (обычно 64 МиБ) — ок.
   Разблокированный загрузчик обязателен (иначе LK откажется грузить неподписанное).
4. **Как ведёт себя PMIC/RPM после LK?** LK уже включил eMMC-питание и DDR; если
   UEFI не выключит эти регуляторы, eMMC может работать «бесплатно». Это главная
   надежда на дешёвый старт — и её надо проверить экспериментом, а не верой.

## Что реалистичнее для задачи «грузить любые системы»

Полноценный UEFI даёт: ISO-образы, GRUB, Windows-загрузчик, единый стандарт.
Но для этого телефона практический путь такой:

1. **Linux-дистрибутив с custom-ядром** (Debian/Ubuntu/Alpine/postmarketOS) —
   грузится штатной цепочкой LK → boot.img, без UEFI. Ядро + initramfs + rootfs
   на microSD или в разделе `userdata`. Это уже «любая система» в смысле Linux.
2. Позже, если порт UEFI взлетит — тот же rootfs грузится через UEFI + GRUB.

См. `06-boot-any-os.md`.

## Итог

Проект имеет смысл **только если проба G0 дала PASS** и вы готовы к итерациям
«собрал → залил → посмотрел на экран → прислал вывод». Всё остальное (готовый
образ «прошей и грузи Windows») — невозможно, и любой, кто обещает обратное,
либо не понимает объём работ, либо продаёт что-то другое.
