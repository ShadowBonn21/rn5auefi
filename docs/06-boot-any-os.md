# 06. Что реально можно «загружать» на этом телефоне

## Матрица возможностей

| Что | Возможно | Чем | Комментарий |
|---|---|---|---|
| Linux-дистрибутив (Debian/Ubuntu/Alpine/Arch ARM64) | **Да** | UEFI+GRUB **или** прямой boot.img с ядром | работает и без UEFI-порта |
| postmarketOS / mainline-ядро | **Да** | boot.img + DTB | для msm89x7 есть community-работы |
| Live-ISO с microSD/USB | Да, но… | UEFI + GRUB + USB/microSD | требует драйверов eMMC/USB (G3/G5) |
| Android/TWRP | Да | штатный LK, без UEFI | UEFI тут не нужен |
| Windows on ARM | **Нет** | — | нет ACPI-таблиц, драйверов GPU/тача/модема; никто не портировал 89xx |
| x86-софт | Нет | — | другая архитектура (только эмуляция, медленно) |

## Путь 1 (рабочий уже сейчас): Linux без UEFI

LK умеет грузить `boot.img` с ядром и initramfs. Значит:

1. Собрать ARM64-ядро для msm8937 (или взять готовое community-ядро) + DTB платы.
2. Собрать `boot.img`: kernel + DTB + initramfs, где initramfs монтирует rootfs
   с microSD или из раздела `userdata`.
3. `fastboot boot boot-linux.img` → устройство грузится в Linux с консолью
   на framebuffer (simplefb) и/или через USB (`g_ether`/RNDIS → ssh).

Это даёт «любую систему» в смысле любого Linux-дистрибутива: rootfs можно
положить на microSD (ext4), в образ (ext4 в разделе), или тянуть по сети.

Плюсы: не нужен порт UEFI, работает на существующем загрузчике.
Минусы: нет единого стандарта загрузки (GRUB/ISO), нет Windows, каждое ядро
требует своего DTB/cmdline.

## Путь 2 (то, что мы строим): UEFI + GRUB

Когда пройдены G3 (eMMC) и G5 (USB):

```
LK → boot.img (BootShim + UEFI) → UEFI Shell/SimpleInit → GRUB.efi → Linux
```

Что появляется:
* загрузка **любого** EFI-загрузчика (GRUB, systemd-boot, rEFInd);
* ISO-образы: распаковать на FAT-раздел или подключить USB-флешку;
* единый `\EFI\BOOT\BOOTAA64.EFI` — как на обычном ПК;
* возможность ставить дистрибутив «как на ПК» (с оговорками по драйверам).

Что **не** появляется:
* Windows (нужен ACPI + драйверы, которых нет);
* изменение разрешения/режимов экрана (панель включает LK, UEFI только рисует
  в уже готовый буфер `0x90000000`);
* надёжная работа при выключенном LK-питании периферии (см. G3).

## Как выглядит «загрузка любой системы» на практике

1. microSD 16+ ГБ, GPT: раздел 1 FAT32 (`EFI`), раздел 2 ext4 (`root`).
2. На FAT: `\EFI\BOOT\BOOTAA64.EFI` (GRUB), `\EFI\linux\vmlinuz-*`, `\EFI\linux\initrd-*`.
3. В UEFI: `map -r` → `fs0:` → `\EFI\BOOT\BOOTAA64.EFI` (или автостарт).
4. GRUB грузит ядро с `console=tty0` и DTB — Linux стартует.

Для «любой системы» достаточно менять содержимое FAT/ext4 — UEFI-прошивка
при этом не меняется.

## Ограничения, о которых лучше знать заранее

* **Панель**: инициализируется загрузчиком (LK). Если LK не включил дисплей
  (например, после неудачного ребута), UEFI покажет чёрный экран, хотя всё работает.
* **Батарея/зарядка**: без драйвера PMIC UEFI не умеет показывать заряд и может
  не заряжать в выключенном состоянии — не оставляйте телефон разряженным в UEFI.
* **Модем/Wi-Fi/BT**: под UEFI не работают (это нормально, как на ПК без драйверов).
* **Тепло**: 8× A53 без governor в UEFI греются; длительная работа в UEFI-консоли
  нежелательна.
